Goal: Build a home/landing page for Investment Company (Developer-role) users, matching the existing Catalyst "Good morning, Jack" launchpad pattern (client/src/pages/launchpad.tsx) — their name, live market rates, a quick pipeline overview, and a section of their own saved tool/software links — and make it what they land on right after login instead of the deal dashboard.

Schema — new table developerQuickLinks in shared/schema.ts: id, developerProfileId (FK → developerProfiles, cascade delete), label (varchar, required), url (varchar, required), sortOrder (integer, default 0), isActive (boolean, default true), createdAt/updatedAt. Keep it this simple — no icon field. Since these are arbitrary user-entered links, render every one with a generic link icon rather than trying to match a curated icon per link; that avoids needing an icon picker or icon-name validation.
Server endpoints — add to server/routes.ts, following the exact getDeveloperProfileId(req, res) / requireActiveDeveloperProfile(developerProfileId, res) pattern already used for other developer-scoped endpoints (search that pattern to match it exactly):
GET /api/developer/quick-links — returns the current developer's active links, sorted by sortOrder.
POST /api/developer/quick-links — create a link for the current developer's profile only.
PATCH /api/developer/quick-links/:id — update label/url/sortOrder/isActive, but only if the link's developerProfileId matches the requesting developer's own profile (return 404 otherwise — never let one investment company edit another's links).
DELETE /api/developer/quick-links/:id — same ownership check.
New page client/src/pages/developer-home.tsx — same visual structure as launchpad.tsx's Market Rates and Pipeline Overview sections, reusing the same /api/market-metrics and /api/deals/stats queries completely unchanged (don't touch either endpoint's logic). For the greeting, use the logged-in user's actual firstName from their account (already available via useAuth()/the user object) instead of parsing it out of their email — that field already exists on users. Show the investment company's name (developerProfile.companyName) as a subtitle. Add a "Your Tools" section below Pipeline Overview: fetch /api/developer/quick-links and render each as a clickable card/list item (label + external-link icon, opens in a new tab) — matching the existing ListItem visual pattern in launchpad.tsx. If there are zero links yet, show a simple empty state with a link to Settings rather than an empty section.
Settings UI — add a "Quick Links" section to client/src/pages/developer-criteria-settings.tsx, same rounded-2xl/bg-white card styling as the rest of that page. A simple list of the developer's current links, each with an edit and delete action, plus an "Add Link" row with two fields (Label, URL) and a save button. No drag-and-drop reordering for now — keep it to add/edit/delete, which is enough to be useful without adding UI complexity that could break.
Routing — in client/src/App.tsx, add a route /developer/home → DeveloperHome, and change the DEVELOPER-role default-landing fallback (the block that currently does window.location.replace(home) picking between /developer/crm for general_sales and /dashboard otherwise) so that for the normal (non-general_sales) profile type, the default becomes /developer/home instead of /dashboard. Leave the general_sales branch pointed at /developer/crm exactly as it is today — that profile type has no deal dashboard tab at all, so a pipeline-overview-first home page doesn't fit them; don't change their landing behavior. Also add a "Home" tab as the first entry in realEstateTabs in client/src/components/developer-navigation.tsx, pointing to /developer/home, so users can get back to it from anywhere. Keep /dashboard and /developer/dashboard working exactly as they do today (still load the deal dashboard) — this change only affects what loads first after login, not any existing bookmarked or linked route.

Non-regression: don't modify /api/market-metrics, /api/deals/stats, AnalystDashboard, or anything in the general_sales profile-type branch. This is purely additive — a new table, new scoped endpoints, one new page, one new settings section, and one line changing which route a normal Developer-role user lands on after login.
