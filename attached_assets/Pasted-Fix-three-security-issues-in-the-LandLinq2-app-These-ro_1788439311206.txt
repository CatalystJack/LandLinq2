TASK 3 — Sanitize the public deal-sharing endpoint
GET /api/deals/:id (~line 7615) is intentionally public (no auth) for deal-sharing 
purposes, but currently returns the ENTIRE deal record plus the full broker object 
(including broker email/phone) to anyone with a valid or guessed UUID.

3a. Add a new table to shared/schema.ts:

export const dealShareTokens = pgTable("deal_share_tokens", {
  id: varchar("id").primaryKey().default(sql`gen_random_uuid()`),
  token: varchar("token").notNull().unique(),
  dealId: varchar("deal_id").references(() => deals.id).notNull(),
  createdBy: varchar("created_by").references(() => users.id),
  expiresAt: timestamp("expires_at").notNull(),
  createdAt: timestamp("created_at").defaultNow(),
});

3b. Add a new authenticated route to generate a share link:
POST /api/deals/:id/share (isAuthenticated)
  - Creates a dealShareTokens row with a random token (crypto.randomUUID() or similar) 
    and expiresAt = now() + 7 days (adjustable, but must have a real expiry)
  - Returns the shareable URL: /api/deals/:id?token=<token>

3c. Modify GET /api/deals/:id:
  - Require a valid, non-expired ?token= query param matching a dealShareTokens row 
    for this dealId. Return 401/403 if missing or invalid/expired.
  - Return a SANITIZED projection only: address, city, state, sizeAcres, askingPrice, 
    productType, description, and any high-level analysis fields appropriate for 
    external sharing. Do NOT include: broker object, broker email, broker phone, 
    document URLs, internal notes, or any internal classification/scoring fields.
  - Keep the existing UUID format validation and 404-if-not-found behavior.

3d. Update any frontend code that currently generates or uses a /api/deals/:id link 
for sharing purposes to call the new /share endpoint first and use the token-bearing 
URL, rather than linking directly to the bare deal ID.

Verify after all three tasks: existing internal pages that rely on GET /api/deals/:id 
(if any use it while logged in) still work — check if the internal admin/analyst UI 
also hits this same public route, and if so, give it a separate internal-only route 
returning the full record instead of breaking that flow.
