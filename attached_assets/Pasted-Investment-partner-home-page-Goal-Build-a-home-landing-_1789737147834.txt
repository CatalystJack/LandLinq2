Investment partner home page

Goal: Build a home/landing page for Investment Company (Developer-role) users, matching the existing Catalyst launchpad pattern (client/src/pages/launchpad.tsx) — their name, live market rates, a quick pipeline overview, and a section of their own saved tool/software links — and make it what they land on right after login instead of the deal dashboard.

Schema — new table developerQuickLinks in shared/schema.ts: id, developerProfileId (FK → developerProfiles, cascade), label (varchar, required), url (varchar, required), sortOrder (integer, default 0), isActive (boolean, default true), createdAt/updatedAt. No icon field — render every link with a generic link icon.
Server endpoints in server/routes.ts, following the existing getDeveloperProfileId(req, res) / requireActiveDeveloperProfile(...) pattern used elsewhere for developer-scoped data:
GET /api/developer/quick-links — the current developer's active links, sorted by sortOrder.
POST /api/developer/quick-links — create, scoped to the requester's own profile.
PATCH /api/developer/quick-links/:id and DELETE /api/developer/quick-links/:id — only if the link's developerProfileId matches the requester's own profile (404 otherwise).
New page client/src/pages/developer-home.tsx — same Market Rates and Pipeline Overview sections as launchpad.tsx, reusing /api/market-metrics and /api/deals/stats completely unchanged. Greet using the logged-in user's actual firstName (already on the users table via useAuth()), with developerProfile.companyName as a subtitle. Add a "Your Tools" section below it, fetching /api/developer/quick-links and rendering each as a clickable card (label + external-link icon, opens in a new tab), matching the ListItem pattern in launchpad.tsx. Empty state links to Settings.
Settings UI — add a "Quick Links" section to client/src/pages/developer-criteria-settings.tsx, same card styling as the rest of the page: a list of current links with edit/delete, plus an "Add Link" row (Label, URL, Save). No drag-and-drop reordering needed.
Routing — in client/src/App.tsx, add /developer/home → DeveloperHome, and change the DEVELOPER-role default-landing fallback so the normal (non-general_sales) profile type defaults to /developer/home instead of /dashboard. Leave the general_sales branch pointed at /developer/crm exactly as today. Add a "Home" tab as the first entry in realEstateTabs in client/src/components/developer-navigation.tsx, pointing to /developer/home. Keep /dashboard and /developer/dashboard working exactly as they do today.

Don't modify /api/market-metrics, /api/deals/stats, AnalystDashboard, or the general_sales branch.
