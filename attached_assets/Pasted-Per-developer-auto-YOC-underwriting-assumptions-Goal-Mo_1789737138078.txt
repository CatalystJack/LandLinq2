Per-developer auto-YOC underwriting assumptions

Goal: Move LandLinq's existing auto-YOC underwriting engine (calculateYOCForProductTypes and calculateYOCBreakdown, currently in client/src/pages/analyst-dashboard.tsx starting around line 1741) from client-side to a shared server service, and let each developer group override the national PRODUCT_TYPE_YOC_PRESETS with their own assumptions, entered through a settings form. Do not simplify or drop any of the existing modeling logic (vacancy/LTL/concessions/bad debt, management fee, coastal insurance tiers, state-level rent/land multipliers, NC sub-market overrides, HelloData comp-based rent for conventional/BTR, the "BEST" multi-type comparison) — this needs to stay exactly as thorough as it is today, just parameterizable per developer.

Schema — extend the existing developerProductTypes table (shared/schema.ts, already has developerProfileId, name, minAcres, maxAcres, minRentPsf, minRentPerUnit) with new nullable columns matching the shape of PRODUCT_TYPE_YOC_PRESETS: dua, hardCostPu, assumedLandCostPu, assumedLandCostPuCoastal, softCostPct, otherIncomePum, fixedOpExPu, insurancePuNc, insurancePuCoastal, vacancyPct (default 0.05), ltlPct (default 0.01), concessionPct (default 0.01), badDebtPct (default 0), mgmtFeePct (default 0.0275), and unitMix (jsonb, array of {pct, avgSF, monthlyRent}). All nullable — a developer with none of these set falls back to the existing global preset unchanged.
Server — extract the calculation into server/services/yocUnderwritingService.ts. Port calculateYOCForProductTypes and calculateYOCBreakdown nearly verbatim (same math, same coastal/state-multiplier logic, same comp-based rent logic), but change the preset lookup: first check whether the deal's developerProfileId has a matching row in developerProductTypes with underwriting fields populated (non-null hardCostPu) for that product type name; if so, build the preset object from those fields instead of the hardcoded table. Keep PRODUCT_TYPE_YOC_PRESETS as the fallback default.
Auto-recompute on change, server-side. Trigger recomputation whenever: (a) a deal is created or its productTypes, unitCount, sizeAcres, or askingPrice changes, and (b) whenever a developer's developerProductTypes underwriting fields are updated — recompute automatedYoc for every existing deal tied to that developer with a matching product type, not just new deals. Respect the existing yocOverrides per-deal manual override — it still wins over the auto-calculated value.
Settings UI (in-app form) — add an "Underwriting Assumptions" section to client/src/pages/developer-criteria-settings.tsx, same rounded-2xl/bg-white card styling as the rest of that page. For each product type, labeled numeric fields for every column added in step 1, plus a small repeatable unit-mix table. Leaving a field blank means "use the national default."
Client cleanup — replace the client-side calculation in analyst-dashboard.tsx with a read of the server-computed deal.automatedYoc (already read today); remove the now-redundant client functions once the server service is confirmed working.

Test with one deal whose developer has custom assumptions, and one whose developer has none set — the no-override case must produce the exact same result as today's calculation.
