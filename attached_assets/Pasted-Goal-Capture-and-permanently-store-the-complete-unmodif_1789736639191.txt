Goal: Capture and permanently store the complete, unmodified raw response from every HelloData API call, in addition to (not instead of) the existing curated data. This is a pure archive — nothing that currently reads or displays comp data should change.

Schema — new table helloDataRawResponses in shared/schema.ts: id (uuid, primary key), endpoint (varchar — e.g. "property/comparables", "property/pricing", "property/search", "property/:id"), requestParams (jsonb — whatever query params/body were sent), rawResponse (jsonb — the exact, unmodified response.json() result, no filtering or mapping), dealId (varchar, nullable FK → deals, no cascade needed — just for traceability, can be null for calls not tied to a specific deal), fetchedAt (timestamp, default now). No expiry — this is meant to be kept indefinitely, unlike the 3-month market_comp_cache.
Capture point — in server/hellodataService.ts, wrap the five raw-fetch call sites (property/search ~line 737, property/:id ~line 847, property/comparables ~line 989, and the three property/pricing calls ~lines 1669, 1901, 2860) with a single shared helper, e.g. archiveRawHelloDataResponse(endpoint, requestParams, rawResponse, dealId?), called right after each await response.json() — before any filtering, mapping, or field renaming happens. Insert into helloDataRawResponses inside a try/catch that only logs a warning on failure and never throws — this archive must never block or break the actual comparable search, exactly like the failure-tolerant pattern already used for census/permit enrichment elsewhere in this codebase.
Nothing else changes. Don't touch comparablesJson, market_comp_cache, searchQualifyingComparables's return shape, or any of the three places that build a deal's curated comparables. This table is write-only from the app's perspective for now — no new UI, no new endpoint reading it, no change to existing behavior. The point is simply that from today forward, nothing HelloData ever sends you gets thrown away.
