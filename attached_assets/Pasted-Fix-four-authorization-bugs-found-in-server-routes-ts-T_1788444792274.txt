Fix four authorization bugs found in server/routes.ts.

TASK 1 — CRITICAL: Remove the backdoor clear-deals route
POST /api/admin/clear-deals (~line 20361) has NO authentication middleware at all, 
and is gated only by a hardcoded bearer token ('CLEAR_DEALS_2025') visible in source 
control. This route TRUNCATEs the deals and communications tables entirely.

Fix: Add isAuthenticated and requirePlatformAdmin middleware to this route, and 
DELETE the hardcoded token check entirely — it provides no real security once proper 
auth is in place and should never have been the only protection on a destructive 
route. If this route is only ever meant for local/dev database resets, also add a 
check that NODE_ENV !== 'production' and reject with 403 in production regardless 
of who's calling it, as a second layer of protection against ever running this 
against real data.

TASK 2 — Lock down template/reason-seeding routes
GET /api/admin/populate-templates (~line 20008) and 
GET /api/admin/populate-rejection-reasons (~line 20054) are fully public with no 
auth check, and both write to the database on a GET request.
  - Add isAuthenticated and requirePlatformAdmin middleware to both
  - Change both from GET to POST, since they perform writes — a GET request should 
    never have side effects. Update any frontend code calling these routes to use 
    POST instead.

TASK 3 — Lock down broker-portal deal approval
PATCH /api/admin/broker-portal/deals/:dealId/approve (~line 14377) has no role 
check beyond isAuthenticated, despite approving deals for broker visibility and 
triggering real outbound emails to brokers.
  - Add the same admin check pattern already used elsewhere in this file: 
    user?.email?.endsWith('@apexresi.com'), returning 403 if not met
