Add a generic, industry-agnostic pipeline feature for sales seats (profileType = 
'general_sales'), and make it available to real_estate profiles too as an 
additional, separate view alongside their existing Deal Dashboard — this is a 
different concept from real estate deal classification, not a replacement for it. 
This depends on the profileType field added in the previous task.

TASK 1 — Schema

export const pipelineStages = pgTable("pipeline_stages", {
  id: varchar("id").primaryKey().default(sql`gen_random_uuid()`),
  developerProfileId: varchar("developer_profile_id").references(() => developerProfiles.id, { onDelete: "cascade" }).notNull(),
  name: varchar("name").notNull(),
  sortOrder: integer("sort_order").notNull(),
  isActive: boolean("is_active").default(true).notNull(),
});

export const pipelineOpportunities = pgTable("pipeline_opportunities", {
  id: varchar("id").primaryKey().default(sql`gen_random_uuid()`),
  developerProfileId: varchar("developer_profile_id").references(() => developerProfiles.id).notNull(),
  contactId: varchar("contact_id").references(() => brokers.id).notNull(),
  stageId: varchar("stage_id").references(() => pipelineStages.id).notNull(),
  title: varchar("title"),
  value: decimal("value"),
  notes: text("notes"),
  createdAt: timestamp("created_at").defaultNow(),
  updatedAt: timestamp("updated_at").defaultNow(),
});

TASK 2 — Default stages on profile creation
When a new profile is created (either type, via the admin panel — same creation 
flow updated in the previous task), automatically create five default pipelineStages 
rows: "New Lead" (sortOrder 1), "Contacted" (sortOrder 2), "Quoted" (sortOrder 3), 
"Won" (sortOrder 4), "Lost" (sortOrder 5). These are defaults the company can rename, 
reorder, deactivate, or add to afterward — not a fixed/locked set.

TASK 3 — API endpoints
  GET  /api/developer-profile/me/pipeline/stages — list this profile's stages
  POST /api/developer-profile/me/pipeline/stages — add a stage {name, sortOrder}
  PATCH /api/developer-profile/me/pipeline/stages/:id — rename/reorder/deactivate
  DELETE /api/developer-profile/me/pipeline/stages/:id — only allow if no 
    opportunities currently reference this stage; otherwise return a clear error
  GET  /api/developer-profile/me/pipeline/opportunities — list, filterable by 
    ?stageId= query param, sortable by createdAt/value/contact name
  POST /api/developer-profile/me/pipeline/opportunities — create {contactId, 
    stageId, title, value, notes} — contactId must reference a contact owned by 
    this same profile (or the shared network), same ownership rule as elsewhere
  PATCH /api/developer-profile/me/pipeline/opportunities/:id — update any field, 
    most commonly moving it to a new stageId
All endpoints use the existing getDeveloperProfileId(req, res) helper for tenant 
scoping — same pattern as every other developer-profile/me route.
